# GraalVM Native Image Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Switch the app's Docker image from a JVM-based build to a GraalVM native-image build running on `debian:bookworm-slim`.

**Architecture:** Add the GraalVM native-build-tools Gradle plugin, generate and check in Tess4J/JNA-specific reachability metadata via a tracing-agent script, verify a local `nativeCompile` build works against that checked-in config, then rewrite the Dockerfile as a two-stage build (GraalVM build stage → `debian:bookworm-slim` runtime stage running the native executable directly, no JVM).

**Tech Stack:** Gradle 9.7.1, Spring Boot 4.1.1, GraalVM CE 25 (`25.3.4+1.r25-graalce` via SDKMAN), `org.graalvm.buildtools.native` Gradle plugin 1.1.11, Tess4J 5.20.0 (JNA), Docker.

**Spec:** `docs/superpowers/specs/2026-09-13-graalvm-native-image-design.md`

## Global Constraints

- GraalVM version: CE `25.3.4+1.r25-graalce` (SDKMAN candidate), invoked by explicit path — never set as the shell's default JDK.
- Gradle plugin: `org.graalvm.buildtools.native` version `1.1.11`.
- Docker build-stage image: `ghcr.io/graalvm/native-image-community:25i3`.
- Docker runtime-stage image: `debian:bookworm-slim`, with runtime-only packages `libtesseract5 libleptonica5` (no `-dev` packages).
- Reachability metadata file path: `src/main/resources/META-INF/native-image/com.tung/receipt-extractor/reachability-metadata.json`.
- Test fixture for exercising OCR: `src/test/resources/ocr/sample-receipt.png` (expected OCR response includes `"bankSource":"Zalopay"` and `"amount":125000`).
- No new automated unit tests are added anywhere in this plan — per the spec's Testing section, this is infrastructure/build tooling, verified by running real builds/executables, not unit tests.

### Task 2: Write the reachability-metadata regeneration script and generate the initial config

**Files:**
- Create: `scripts/regenerate-native-image-config.sh`
- Create: `src/main/resources/META-INF/native-image/com.tung/receipt-extractor/reachability-metadata.json` (generated by running the script, not hand-written)

**Interfaces:**
- Consumes: the AOT-processed `bootJar` output from Task 1's plugin.
- Produces: `reachability-metadata.json`, consumed by Task 3 (`nativeCompile`) and Task 4 (the Docker build stage, via the same Gradle build).

- [ ] **Step 1: Confirm GraalVM CE is installed locally**

Run: `ls "$HOME/.sdkman/candidates/java/25.3.4+1.r25-graalce/bin/java"`

Expected: the path exists. If not, install it first:

```bash
sdk install java 25.3.4+1.r25-graalce
```

Answer **"n"** when asked whether to set it as default — this must not become the shell's default JDK. If it's accidentally set as default, restore the previous default immediately:

```bash
sdk default java 25.0.2-open
```

(Check `ls ~/.sdkman/candidates/java/` first if the previous default's exact candidate name is unknown — it will be the other entry besides `25.3.4+1.r25-graalce` and `current`.)

- [ ] **Step 2: Write the script**

Create `scripts/regenerate-native-image-config.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

GRAAL_HOME="$HOME/.sdkman/candidates/java/25.3.4+1.r25-graalce"
if [ ! -x "$GRAAL_HOME/bin/java" ]; then
  echo "GraalVM CE 25 not found at $GRAAL_HOME" >&2
  echo "Install it with: sdk install java 25.3.4+1.r25-graalce" >&2
  echo "(answer 'n' when asked to set it as default)" >&2
  exit 1
fi

REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
cd "$REPO_ROOT"

CONFIG_OUTPUT_DIR="$(mktemp -d)"
TARGET_DIR="$REPO_ROOT/src/main/resources/META-INF/native-image/com.tung/receipt-extractor"

echo "Building bootJar (with AOT processing)..."
./gradlew bootJar --no-daemon -q

export SHEETS_CLIENT_ID=dummy SHEETS_CLIENT_SECRET=dummy SHEETS_REFRESH_TOKEN=dummy
export SHEETS_SPREADSHEET_ID=dummy SHEETS_SHEET_NAME=dummy
export TELEGRAM_BOT_TOKEN=dummy TELEGRAM_ALLOWED_CHAT_ID=12345 TELEGRAM_WEBHOOK_SECRET_TOKEN=dummy
export OCR_TESSDATA_PATH="$REPO_ROOT/src/main/resources/tessdata"

JAR_PATH=$(ls "$REPO_ROOT"/build/libs/*.jar | grep -v -- '-plain\.jar$' | head -1)

echo "Starting app under native-image-agent..."
"$GRAAL_HOME/bin/java" -agentlib:native-image-agent=config-output-dir="$CONFIG_OUTPUT_DIR" \
  -jar "$JAR_PATH" > /tmp/regen-native-config-app.log 2>&1 &
APP_PID=$!

echo "Waiting for app to start..."
for i in $(seq 1 30); do
  if curl -s -o /dev/null http://localhost:8080/api/ocr/extract; then
    break
  fi
  sleep 1
done
sleep 3

echo "Exercising OCR endpoint..."
curl -s -f -F "file=@$REPO_ROOT/src/test/resources/ocr/sample-receipt.png;type=image/png" \
  http://localhost:8080/api/ocr/extract > /tmp/regen-native-config-response.json

echo "Stopping app..."
kill -TERM "$APP_PID"
wait "$APP_PID" 2>/dev/null || true

mkdir -p "$TARGET_DIR"
cp "$CONFIG_OUTPUT_DIR/reachability-metadata.json" "$TARGET_DIR/reachability-metadata.json"

echo "Updated $TARGET_DIR/reachability-metadata.json"
echo "OCR response was:"
cat /tmp/regen-native-config-response.json
echo
```

Make it executable:

```bash
chmod +x scripts/regenerate-native-image-config.sh
```

- [ ] **Step 3: Run the script**

Run: `./scripts/regenerate-native-image-config.sh`

Expected: it finishes without error, prints an OCR response JSON body containing `"bankSource":"Zalopay"` and `"amount":125000`, and creates/updates `src/main/resources/META-INF/native-image/com.tung/receipt-extractor/reachability-metadata.json`.

- [ ] **Step 4: Verify the generated config contains Tess4J/JNA entries**

Run: `grep -c "com.sun.jna" src/main/resources/META-INF/native-image/com.tung/receipt-extractor/reachability-metadata.json`

Expected: a non-zero count (dozens of matches), confirming JNA proxy/reflection entries were captured.

- [ ] **Step 5: Commit**

```bash

  src/main/resources/META-INF/native-image/com.tung/receipt-extractor/reachability-metadata.json
git commit -m "Add native-image reachability config and regeneration script
```

### Task 4: Rewrite the Dockerfile for GraalVM native image on `debian:bookworm-slim`

**Files:**
- Modify: `Dockerfile`

**Interfaces:**
- Consumes: `nativeCompile` (Task 1/3), `reachability-metadata.json` (Task 2) — both picked up automatically by the Gradle build the Dockerfile's build stage runs.

- [ ] **Step 1: Replace the Dockerfile contents**

```dockerfile
FROM ghcr.io/graalvm/native-image-community:25i3 AS build
WORKDIR /app
COPY gradlew ./
COPY gradle ./gradle
COPY build.gradle settings.gradle ./
COPY src ./src
RUN ./gradlew nativeCompile --no-daemon

FROM debian:bookworm-slim
RUN apt-get update \
    && apt-get install -y --no-install-recommends libtesseract5 libleptonica5 \
    && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY --from=build /app/src/main/resources/tessdata /app/tessdata
ENV OCR_TESSDATA_PATH=/app/tessdata
COPY --from=build /app/build/native/nativeCompile/receipt-extractor /app/receipt-extractor
ENTRYPOINT ["/app/receipt-extractor"]
```

- [ ] **Step 2: Attempt a local Docker build, if Docker is available**

Run: `command -v docker`

- If a path is printed, run:

  ```bash
  docker build -t receipt-extractor-native-test .
  ```

  Expected: the build succeeds. Then verify it runs:

  ```bash
  docker run -d --name receipt-extractor-native-test -p 8080:8080 \
    -e SHEETS_CLIENT_ID=dummy -e SHEETS_CLIENT_SECRET=dummy -e SHEETS_REFRESH_TOKEN=dummy \
    -e SHEETS_SPREADSHEET_ID=dummy -e SHEETS_SHEET_NAME=dummy \
    -e TELEGRAM_BOT_TOKEN=dummy -e TELEGRAM_ALLOWED_CHAT_ID=12345 -e TELEGRAM_WEBHOOK_SECRET_TOKEN=dummy \
    receipt-extractor-native-test
  sleep 3
  curl -s -f -F "file=@src/test/resources/ocr/sample-receipt.png;type=image/png" \
    http://localhost:8080/api/ocr/extract
  docker rm -f receipt-extractor-native-test
  ```

  Expected: the same `"bankSource":"Zalopay"`/`"amount":125000` JSON response as Tasks 2 and 3.

- If no path is printed (Docker not installed in this environment), skip execution and record in the task's completion notes: *"Docker is not available in this environment; the Dockerfile change is committed on the strength of Task 3's local `nativeCompile` + native-executable verification (same build stage command, same checked-in config) and structural review.
